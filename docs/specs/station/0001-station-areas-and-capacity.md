# 0001 片区责任与当班人员

Status: ready-for-agent

## 问题陈述

网点员工按固定片区分堆。网点调度需要知道每个片区平时谁负责、当前谁在岗，以及有人请假、入职或调整责任片区后，当前可安排人员有哪些。

## 解决方案

建立本网点的片区、配送员和班次名册。操作员按网点查有效配送片区，网点调度可以登记新配送员、班次和请假，维护片区常规责任。配送计划查指定时点的人员和片区关系，临时调整具体包裹由网点调度在计划中确认。

## 用户故事

1. 作为网点操作员，我希望查看本网点启用的配送片区，以便分货时使用一致的片区标识。
2. 作为网点操作员，我希望按配送片区查看平时的责任人，以便知道日常按谁负责的片区备货。
3. 作为网点调度，我希望维护网点配送员与常规片区责任，以便排班时有明确的人员归属。
4. 作为网点调度，我希望录入配送员的班次起止，以便判断指定时点谁在岗。
5. 作为网点调度，我希望在指定时点查到在岗的本片区责任人，以便知道常规配送能否由原责任人执行。
6. 作为网点调度，我希望更新请假与在岗情况，以便排计划时看清常规责任人是否可用。
7. 作为网点调度，我希望新增配送员并登记班次，以便他在实际到岗后能参与配送。
8. 作为网点调度，我希望可以更新长期的片区责任关系，以便按新的日常分工备货。
9. 作为包裹履约的调用方，我希望能校验一个配送片区属于当前网点，以便按同一口径登记片区和提示分货。
10. 作为配送计划的调用方，我希望按指定时点读取常规责任和本网点当班人员，以便生成建议和校验网点调度的人工选择。

## 实现决定

- 网点与运力持有网点、下属驿站、配送片区、配送员、班次、请假和片区常规责任。一个网点可有多个下属驿站和片区。一片区可配置一位网点直派常规责任人，同一网点配送员可负责多个片区。驿站配送员单独绑定具体驿站。
- 查询片区返回网点内稳定的片区标识、名称、启用情况和常规责任人。分货时可按片区标识和名称核对。片区标识在人员变动时仍可用于查询包裹。此规格使用已识别的片区标识作为输入。
- 班次记录配送员和起止时间，查询时点达到开始时间且早于结束时间时命中。网点、启用状态、班次和请假一起决定在岗人员查询结果。常规责任人缺岗时仍可查询责任关系，并看到该责任人当前不可用。
- 调度或站长按配送员的一条班次记录登记整班请假。新增排班时，同一配送员的班次时段不得重叠，前一班结束时点可以作为下一班的开始时点。重叠检查与班次成员写入在同一事务中完成，同一配送员的并发排班在写入前逐笔核对已有班次。
- 新配送员登记后进入所属网点或驿站的名册，在有效班次内才显示在本单位当班人员列表。更新片区常规责任供新的安排读取，原计划和历史交接按当时记录查询。
- 网点与运力维护人员档案和在岗事实。人员请假只影响当班安排，员工账号的开通、停用与凭据由账号与身份管理。
- 网点调度维护本单位转运司机档案，供网点向驿站分拨时指派。转运司机按分拨批次提供运力。
- 实现沿用 Spring Boot、JDBC、Flyway 和 MySQL。应用服务使用可信的所属单位。网点调度维护网点人员、片区与下属驿站关系，驿站站长维护本驿站人员与班次。测试以合成名册和固定时点运行。
- 包裹履约持有到站扫描、运单状态和实际交接记录。配送计划持有具体包裹的安排。调用方通过片区查询和当班运力查询读取本网点数据。

## 员工会话下的排班入口

网点调度可使用以下同源接口。服务端从员工会话取得岗位、所属网点和操作人，所有写请求校验 CSRF。标识和版本使用十进制字符串，接口传输时间使用 UTC。页面按员工会话给出的网点时区录入班次、查询当班和显示结果。例如江岸网点录入 08:00–12:00 时，接口时间为 00:00Z–04:00Z，保存后页面显示 08:00–12:00。时钟切换导致本地时间不存在或对应两个时点时，页面提示改选时间。

| 接口 | 输入与结果 |
| --- | --- |
| `GET /api/v1/staff/shift-couriers` | 分页查询本网点启用的配送员，含尚未排班的人员。 |
| `GET /api/v1/staff/shifts?at=…` | 分页查询指定时点覆盖的班次成员，返回配送员、班次起止、在岗或请假状态及版本。已请假成员仍可在班次名单中查询。 |
| `POST /api/v1/staff/shifts` | 提交 `workerId`、`code`、`startsAt`、`endsAt`，成功返回班次标识并记录操作人。同人时段重叠或同名共享班次的时间冲突时返回 `409 SHIFT_CONFLICT`。 |
| `POST /api/v1/staff/shifts/{shiftId}/members/{workerId}/duty-status` | 提交 `status`（`ON_DUTY` 或 `ON_LEAVE`）和 `expectedVersion`。成功后更新操作人和版本。旧版本返回 `409 SHIFT_VERSION_CONFLICT`，页面刷新名单供调度核对后重新提交。 |

Flyway V4 为班次成员增加操作人和版本。已有排班保留原状态，版本从 `0` 开始，历史操作人留空。

## 测试决定

当前只有 Spring Boot 上下文与 MySQL Testcontainers 测试骨架。首轮从 `station` 应用服务的业务入口写测试，使用合成数据与固定时间，核对查询或操作的结果以及提交后可重新读取的记录。共享查询使用同一套验收样例供后续模块联调。

| 场景 | 可验收结果 |
| --- | --- |
| 分货前查询东区 | 只返回本网点的有效片区，东区常规责任人可查。其他网点的片区无法被用来配置本站。 |
| 小陈负责东区、当前班次请假 | 东区常规责任仍显示小陈，当前可安排人员中没有小陈。 |
| 新增本网点配送员并登记有效班次 | 班次开始后可查到此人，片区常规责任保持原值。 |
| 同网点同时存在网点配送员、甲驿站和乙驿站配送员 | 网点直派名单只含本网点运力。甲驿站当班名单只含甲驿站人员。 |
| 以班次开始、班次结束的时点查询 | 班次开始时可查该员工，结束时退出当班名单。 |
| 同一配送员已排 08:00–12:00，再排 10:00–14:00 或 12:00–16:00 | 拒绝时段重叠的安排，允许首尾相接的安排。并发提交相互重叠的两个新班次时，最多一条成员记录写入成功。 |
| 调整东区的常规责任人 | 通过同一个片区标识可查到新责任人。 |
| 提交外网点人员或无效班次区间 | 操作被拒绝，重新读取时既有配置仍完整。 |
| 接入员工会话后，从配置 HTTP 入口维护片区规则与运力 | 网点调度只能维护本网点资源。外网点调度和本网点操作员的配置请求被拒绝，规则、名册和变更记录保持原样。 |

## 范围之外

- 扫码入站、提供上游应到数据、按运单查包裹进度与核实签收争议，归后续包裹履约规格。
- 具体包裹的临时分配归计划，按趟实领件数和交接差异归履约。装载量估算、车辆尺寸和重量参数不在本规格内。
