# 0001 驿站分拨、扫码入库与对账

Status: ready-for-agent

## 问题陈述

网点收到一批件，要把已有上门约定的件留给网点配送员，把约定驿站自取的件按驿站分拨。驿站站长需要看到本驿站应收哪些件，并能分辨网点还没发、已发未收、收到错件和重复扫码。

## 解决方案

网点调度给指定下属驿站发布逐票清单并指派本网点转运司机。司机从网点接手后运至驿站，和驿站站长当场验货。核对无误的实物一次批量签收，有差异的逐票登记并留在网点责任范围内。

## 用户故事

1. 作为网点调度，我希望按驿站批量分拨已确认自取的件，以便网点与驿站核对同一份清单。
2. 作为网点操作员，我希望只确认实际发出的件，以便知道还有哪些留在网点。
3. 作为驿站站长，我希望和司机核对实物后一次签收正常件，批内拒收或缺失件逐票记录。
4. 作为收件人，我希望驿站实收并备好后看到待领取、地点和取件方式，以便到站自取。
5. 作为转运司机，我希望查看自己负责的批次，并和驿站核对签收、拒收和当场缺失件，以便清楚这一趟交付结果。

## 实现决定

- 网点与运力提供派件网点、下属驿站及点位对应关系。`pickup-station` 管理分拨批次、应收条目和对账视图。`fulfillment` 持有原包裹、实物保管、实际发出、驿站实收与可领取的业务事件。
- 网点调度按已确认的投递约定分流。已确认上门、投柜或交普通商铺的件由网点配送员直派；已确认下属驿站自取的件按点位分拨。无法确定去向时先核对。一票件同一阶段只拥有一个有效的领件或分拨授权。
- 发布先记应收。网点操作员与指派司机核对实物并确认接手，逐票记录实际发出、外观验收结果及转运经手人。司机限本人批次，驿站站长限本驿站。发出时仍在隔离待核的网点异常件不得装车。
- 到站后，司机与驿站站长现场按实发清单核对。站长签收本次核对正常件，使用一次批量提交并逐票追加收货事件。破损、错件、缺件分别登记「驿站未签收」及原因、现场凭证和经手人。正常件签收和差异按当次交接提交，重复提交复用原结果。
- 批次并列显示已分配未发、已发待验收、已签收，以及到场核对后的未签收差异。网点发出时记录完好、到驿站现场发现异常的，先归网点至驿站转运交接，由网点复核。异常件保持原保管链，能原车带回的实物由司机带回给网点并确认交还，缺件记待查。只有已签收件进入驿站正常库存。
- 获收件人确认继续配送的外包装破损件，如约定交到驿站，需站长按此前照片和异常标记逐票核对后另行接收，保留当面验收要求。现场发现新增破损时登记具体差异。驿站签收后至下一次实际交出前的保管由驿站负责。
- 驿站分拣员在站长签收后扫码上架，记录操作人和货架。已备好且符合自取约定时登记可领取，收件人页面和通知读取这笔履约事件。实际交给取件人后，由站长凭取件确认记录登记已领取。

## 测试决定

从调度发布、司机接车及驿站验收的 HTTP 入口验收。使用一个网点、两个下属驿站及合成运单。对发出、批量签收重试与保管权校验使用真实 MySQL，同时核对台账和逐票事件。

| 场景 | 可验收结果 |
| --- | --- |
| 一票确认上门，两票确认给甲驿站自取 | 上门件只在网点直派清单；两票自取件进入甲驿站应收清单。仅发布时两票仍由网点保管。 |
| 网点交出 20 件，司机到站后与甲核对，其中 18 件完好、1 件破损、1 件缺失 | 甲一次签收 18 件。破损和缺失逐票标为未签收，由网点跟进。破损件有司机交还网点的后续记录，缺件保持待查。 |
| 已登记外包装破损且收件人同意继续送的件交到驿站 | 按原留证单独核对接收，原破损记录和当面验收标记继续可查。驿站保管期间新增的破损另记。 |
| 甲重复提交签收，乙尝试签收甲的批次，其他司机尝试操作 | 重复签收只计一次。错误驿站或非指派司机的操作被拒绝。 |
| 驿站实收、备好可领取，收件人实际到站领取 | 先展示驿站库存与可领取信息，确认领走后记录领取时间和实际交接。 |

## 范围之外

- 跨网点干线分拨、上游装运接口与独立转运排班。
- 已入驿站后改上门及计件，见[驿站上门与续派](0002-home-delivery-service.md)。
