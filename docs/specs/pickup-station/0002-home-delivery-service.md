# 0002 驿站上门、失败续派与配送员计件

Status: ready-for-agent

## 问题陈述

包裹已入驿站后，收件人可能来电要求送上门。驿站站长需要安排本站配送员、核对免费投递次数，并在两次未妥投后与收件人确认自取或续派。驿站需要按已完成的服务核对配送员计件。

## 解决方案

驿站站长核对来电收件人、运单、送达地址及本站实物，确认上门服务并指派给同一驿站的配送员。前两次投递免费。两次未妥投后由本驿站扫码收回，联系收件人确认自取或协商续派。成功交付后为实际完成者记一笔计件记录。

## 用户故事

1. 作为收件人，我希望电话确认已入驿站的包裹改为上门，并知道免费次数及后续可选方式，以便安排收件。
2. 作为驿站站长，我希望看到已分配给谁、谁实际领走和送达，以便处理改派及查件。
3. 作为驿站配送员，我希望领到本驿站给我的上门件，完成后查到本人计件记录。

## 实现决定

- `pickup-station` 管理上门任务、指派历史、收费续派确认与计件。站长记录客户确认、约定地址和时间。服务首两次投递费用为零，任务由履约提供实际投递次数。同一服务的重试、改派和重新排序沿用原次数。
- 确认服务时以事务核对当前保管状态，并暂停该票的自取领取入口。自取已经确认交付时不能再建任务。站长可在领件前更换本驿站当班配送员，记录操作人和变更。已领件换人走实际转交。网点调度和网点配送员均通过各自的网点权限处理网点作业。
- 被指派的驿站配送员从本驿站扫码领件，沿用工作台和履约接口。首次未妥投可按约再免费投递。两次未妥投后由驿站扫码收回，保留已发生的尝试和实际保管。联系上后可恢复自取，也可事先告知收费标准和本次费用，经收件人同意并记录后再续派。用户费用与配送员计件分别记录。电话未接通或客户尚未同意时保持待联系或待协商。
- 成功上门交付时，在同一 MySQL 事务提交服务完成、实际交付事件及该任务的一笔计件记录。计件记实际完成者和完成时间，可用驿站配置的演示单价计算应计金额。重复确认、领取前取消和投递失败均不能重复或提前计件。查账可按驿站、配送员与完成日期核对。

## 测试决定

从驿站站长受保护的服务入口与配送工作台验收。使用两个下属驿站、网点配送员和同驿站两名配送员。领取和改上门并发、签收重试及计件事务回滚用真实 MySQL。

| 场景 | 可验收结果 |
| --- | --- |
| 驿站实收后，收件人来电改上门 | 服务收费为 0。查到申请、约定、指派人及当前保管地点，实际领件后才显示配送中。 |
| 站长先指派甲，领件前再改指派乙，或跨驿站人员试图领件 | 指派历史保留，只允许当前同驿站乙领件。 |
| 乙成功送达，重复提交同一结果 | 服务和签收各记一次，乙有一笔计件，甲和网点配送员没有这笔计件。 |
| 第一次未妥投后重报，再实际投递第二次仍联系不上 | 重报只记一次，第二次收费仍为 0；该件交回本驿站后显示待联系。 |
| 两次未妥投后客户选择自取或同意有偿续派 | 恢复自取后可核验领取。选择收费续派时先记录告知和同意、再生成领件授权。未同意时不生成收费续派任务。 |
| 投递失败、已入站自取先完成，或计件写入失败 | 失败交付保留实际责任且不产生计件；先完成自取的件不可再建服务；计件写入失败时成功结果一起回滚。 |

从真实派工与计件 HTTP 入口验证甲站长只能将本站任务派给本驿站配送员。乙站长、上级网点调度和分拣员代派工，以及甲站长选择外站配送员均拒绝，原任务指派、授权及保管不变。驿站配送员只能读到本人的已完成计件。换成同站同事、外站人员或网点配送员，均无法读取该员工的计件。

## 范围之外

- 实际扣费、发薪及结算打款。
- 寄件预约揽收、第三方柜机取回和线上自助改投。
