# 0001 在途位置与剩余路程

Status: ready-for-agent

## 问题陈述

收件人催件时，网点需要按运单查这票件实际由谁配送、配送员最近在哪里上报了位置、送到这票前还有几站。配送员可能临时调整顺序，网点需要按最新确认的安排查看沿途距离和行驶时间。

## 解决方案

配送员从手机工作台上报本人当前趟次的位置，Redis 保存最近的有效点位。网点在查件页查看实际配送员、最近位置和采集时间。系统按履约记录与配送员确认的停靠顺序计算前面还有几站，再按需调用高德计算沿途路程和行驶时间。

## 用户故事

1. 作为配送员，我希望工作台在获得定位授权后上报本人当前趟次的最近位置，以便网点查到配送进度。
2. 作为配送员，我希望能确认并调整本趟停靠顺序，以便网点按现在的安排查件。
3. 作为网点员工，我希望按运单看到实际配送员、最近的位置及其采集时间，有地址时知道他在哪条路附近，以便答复催件。
4. 作为网点员工，我希望知道目标站前还有几站、沿途还有多远，以便说明当前配送进度。
5. 作为网点员工，我希望位置过期或高德失败时仍能查已知履约进度，以便继续答复收件人。

## 实现决定

- `presence` 从服务端身份取得配送员及所属网点或驿站。两类配送员只上报本人有效趟次。网点的精确位置查询限本网点直派，驿站的精确位置查询限本驿站上门配送。按运单取实际配送员与趟次，进入待返站、已回库、已交接到网点或已完成投递后，查询展示对应履约事实。待返站件退出待送路线。
- 工作台在获得浏览器定位授权后上报坐标、采集时间、精度和坐标系。后端记录接收时间，在 Redis 中按趟次保存最新点及可配置的有效期。只接受仍有效、采集时间更新的点位，原子替换并刷新有效期。迟到或重复上报保留现有点及其有效期。位置上报不触发高德算路。
- 网点打开位置详情时，可用高德逆地理编码解释最近点位的附近地址。定位点与采集时间独立展示，地址查询失败时仍可查看点位和履约进度。
- 停靠点从本趟实际领件与投递去向得出，演示提供合成停靠点坐标。配送员在工作台确认或调整顺序，履约接口保存趟次内的顺序和版本。已处理完的站从剩余顺序中排除，同站还有待送件时保留一站。临时跳过的站退出本次算路，配送员把它放回确认顺序后可重新计算。目标站暂未进入确认顺序时，仍展示履约进度。
- 剩余站数按目标站之前的未完成停靠点计数，目标站自身不计入。网点请求剩余路程时，以最近有效点位为起点，按确认的途经站点算到目标站。首版演示采用高德电动车路径规划，按相邻两点分段请求，累加道路距离和行驶时间。请求前将需要转换的坐标转成高德使用的坐标系。
- 路程和行驶时间来自同一版停靠顺序和同一个起点点位。返回前复核运单仍在该趟配送、停靠顺序仍有效且所用点位未过期。位置过期或 Redis 不可用时显示「位置暂不可用」。有有效顺序时仍可显示剩余站数。点位、顺序或路段数据不足时，对应路线指标显示暂不可用。
- 向预计送达模块提供计算时间、路线所用点位的采集时间、停靠顺序版本、目标前的停靠点与道路行驶耗时。预计送达时段由估时模块计算。

## 测试决定

从工作台位置上报、停靠顺序调整及网点按运单查件的 HTTP 入口验收。使用合成账号、趟次、运单和停靠坐标。位置过期与乱序使用真实 Redis 验证，算路用模拟高德接口核对请求顺序与返回结果。

| 场景 | 可验收结果 |
| --- | --- |
| 配送员上报本人趟次位置，迟到点随后到达 | 网点查询显示最新有效点的采集时间和位置。迟到点与重复点均不会替换或延长该点的有效期。 |
| 有有效点位，高德返回附近地址或地址查询失败 | 有地址时展示最近点位对应的附近地址。没有地址结果时保留位置和采集时间。 |
| 配送员提交他人趟次位置，或外网点员工查询此运单 | 服务端拒绝访问，对应点位和路线结果保持受限。 |
| 确认的路径为当前位置 → A → B → 目标站，A 有两票待送件 | 目标站前共有两站。若三段分别为 1、2、1 公里，耗时 4、7、4 分钟，页面显示 4 公里、行驶时间 15 分钟。 |
| A 已送完，配送员临时跳过 B 又重新插入，或目标件进入待返站 | 剩余站数和路线按确认的新顺序更新。待返站件展示异常进度、退出待送路线。高德响应晚于顺序变更时，旧路线作废。 |
| 点位过期、Redis 暂不可用或其中一个高德路段失败 | 页面保留能确认的履约状态和剩余站数，缺少有效位置或完整路段时不返回数值型路程与行驶时间。 |
| 配送员只上报位置，网点只查履约状态 | 两个操作均无需调用高德。 |

## 范围之外

- 历史位置轨迹回放、面向收件人的配送员位置展示和自动调整配送顺序。
- 计算预计送达时间段、发送提前到达提醒和履约状态写入规则。
