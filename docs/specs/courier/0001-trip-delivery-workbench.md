# 0001 配送员按趟领件与配送工作台

Status: ready-for-agent

## 问题陈述

配送员需要在同一个工作台找到所属网点或驿站的交接区、确认这趟实际带走哪些件，并在路上记录投递结果。装车时装不下的件要放回原交接区，留待后续趟次。遇到联系不上收件人的件，配送员还需要知道哪些要带回、哪些已由网点确认收回。

## 解决方案

提供面向手机的配送员工作台。配送员登录后查看本人候领清单。首笔领件扫码成功时建立本趟，扫完即可装车发车。装不下的件放回交接区，在回库模式下复扫，恢复未出库。配送中按地址查看本趟待送件，登记实际投递或失败。工作台列出本趟尚待处理的件，实物交接全部结清后可关趟。

## 用户故事

1. 作为配送员，我希望看到本人当班可领件和对应交接区，以便去所属单位已分好的位置直接领件。
2. 作为配送员，我希望连续扫码并看到每票的确认结果，以便核对这一趟实际接手的包裹。
3. 作为配送员，我希望装不下时自己复扫回库，以便把包裹留给后续趟次并修正本次装车数量。
4. 作为配送员，我希望按目的地查看本趟待送件，并看到每票件约定的上门地址或自取点，以便按约定执行。
5. 作为配送员，我希望按实际情况登记上门收件或自取点接收，以便网点与收件人查到同一笔结果。
6. 作为配送员，我希望标记联系不上等失败原因，并看到需要带回的件，以便回站逐件交接。
7. 作为配送员，我希望在请求超时后查证或重试，以便知道刚才的操作是否生效。
8. 作为配送员，我希望看到阻止关趟的具体运单，以便把这一趟的包裹全部交清。

## 实现决定

- `courier` 提供工作台和业务操作入口。`identity` 提供配送员与所属单位。本网点直派从 `planning` 取清单，驿站上门从 `pickup-station` 取已授权任务，`fulfillment` 管理趟次、实物保管、实际领件、配送结果和返站。工作台从这些业务接口读取结果。
- 使用 Vue 3 + TypeScript。领件和装车回库使用明确的扫码模式，兼容键盘式扫码枪、手机摄像头扫码和手工输入。扫码或手工录入统一提交字符串运单号，保留前导零。
- 首笔成功领件建立本趟，后续扫码逐票校验当前有效授权。候领清单显示还可领的件，工作台同时显示本趟实领数。扫码记录的时间表示实际接手时间。
- 已扫码领件的改派要先核实实物及投递状态。配送途中转交时，由调度确认方案、原配送员确认交出、接手人扫码确认；新的保管人以实际接收为准。工作台展示转交进度，改派原因、操作人和交接结果可追溯。
- 回库时核对该件由本人在本趟领到且尚无投递结果或待返站异常。复扫成功后恢复「未出库」，移出本趟实领，追加回库记录。后续趟次重新按当时有效授权领件。
- 工作台显示本趟待送、待返站与已处理的件。上门件显示收件地址、已登记有效投递次数及当前可执行动作。到场投递未妥投时登记尝试时间和原因，重复提交同一次尝试只记一次。单独拨打电话、装车回库等动作保留其各自记录。
- 两次实际免费投递未妥投后，网点直派件有适用本票的改投同意时可送到约定驿站或快递柜，实际交接后更新去向。缺少有效同意时返回网点。驿站上门件由本驿站扫码实际收回，由站长协商自取或续派。收费续派时间和费用按已确认的约定显示。
- 配送员只对本人实际持有的件登记结果。上门交给本人时记录实际收件结果。外部自取点实际接收后登记点位类型、交接时间和凭证，工作台显示实际去向和「待领取」。失败后仍由配送员保管的件，由出发单位的网点操作员或驿站站长扫码收回后才显示返站交接已完成。
- 领件时核对包裹的已有破损和当面验收标记。领件前发现新增破损，登记给出发网点或驿站跟进。标记为待当面验收的件，只有收件人完成检查并确认后才能登记签收。检查发现内损或客户拒收时，登记结果、原因及留证并交回出发单位。破损拒收作为破损异常，不消耗收件人的免费投递次数。交接后新发现的破损关联本次配送环节和当时保管人。
- 接口超时或断线时显示结果待确认。查证或重试复用原操作标识。服务端按已提交状态返回结果，独立的重复扫码也按当前包裹状态校验。关趟前查询本趟仍未结清的运单，交接全部完成后可关趟。

## 测试决定

从配送员工作台的正常操作入口及其调用的 HTTP 接口验收。先用固定数据验证页面，再联调身份、已发布清单和履约业务接口。涉及库存、重试或并发的联调使用真实 MySQL，同时核对页面结果和持久化的交接记录。

| 场景 | 可验收结果 |
| --- | --- |
| 小陈与同事分别登录查看清单，尝试扫对方的件 | 各自只看到本人可领件，越权扫码被拒绝。授权撤销后，旧页面发起的扫码也会被拒绝。 |
| 网点配送员扫驿站上门件，驿站配送员扫网点直派件 | 服务端拒绝领件，所属单位、实际保管和现行授权保持原样。 |
| 甲已领件，调度拟转给乙，乙尚未接手 | 甲仍是实际保管人。乙扫码确认实际交接后，归属变为乙，改派和交接历史均可查。 |
| 当班候领 60 件，本趟扫码领 48 件并重复扫一件 | 首笔成功扫码建立趟次。重复扫码后仍实领 48 件、在站 12 件。页面可直接进入本趟配送。 |
| 其中 1 件装不下，放回后进入回库模式复扫 | 实领 47 件、在站 13 件。该件显示未出库，领件与回库各留一笔记录，网点异常待办计数保持原值。重复回库不改变件数，下趟可凭有效授权领走。 |
| 扫码枪连扫含前导零的运单，请求提交后超时 | 回车后可继续扫码，条码按原值识别。用同一操作标识重试返回已提交结果，实领数只加一次。 |
| 同一趟有上门件和送外部自取点的件 | 工作台逐票显示约定地址和点位类型。实际交接后分别可查上门收件及柜子或商铺的待领取状态和交接时间。 |
| 约定上门的件遇到门禁，尝试直接登记交代收点 | 履约拒绝与现行约定不符的交接结果。经收件人确认改投后，可登记交给约定的代收点。若联系不上且无法上门，则保留失败和待返站记录。 |
| 约定的快递柜已满，配送员尝试交给未获同意的商铺 | 履约拒绝该去向，包裹仍由配送员保管。改投约定中允许该点后，实际交接才能改为待领取。 |
| 两次实际未妥投后，网点直派有有效备用点同意，另一票没有同意 | 前一票可向约定点实际交接，后一票返回网点待跟进。换人重派及失败重报不改变同一服务的累计次数。 |
| 驿站上门件两次实际未妥投，配送员尝试在外点登记代收 | 系统要求交回本驿站，由站长确认实物后办理自取或协商续派。 |
| 已标记破损的件上门交付，收件人检查后分别确认完好或拒收 | 确认后可签收并留验收记录；拒收时记录异常及回交。已有破损证据仍关联原环节。 |
| 配送员登记一票投递完成，另一票联系不上 | 送达件显示实际去向，联系不上的件处于待返站且仍由配送员保管。未交清时关趟显示待处理运单，出发单位确认收回后可以结清。 |

## 范围之外

- 网点转运司机的分拨接车和驿站现场批量交接，见[驿站分拨交接](../pickup-station/0001-transfer-and-receiving.md)。

- 片区与班次配置、草案发布规则、履约状态写入规则和网点异常后续处理。工作台复用对应模块接口。
- 停靠顺序确认及版本、Redis 位置上报、高德算路、FastAPI 估时和收件人客服。相关规格接收已提交的趟次与配送进度。
- 可跨关页保存的完整离线任务队列。

## 补充说明

端到端联调依赖员工登录、已发布的网点直派清单或驿站上门任务，以及履约的领件、回库、投递和返站操作。[在途查件](../presence/0001-trip-location-and-remaining-route.md)以实际趟次和配送进度为输入，并规定停靠顺序确认与算路。 [架构决策 ADR-027 与 ADR-028](../../ARCHITECTURE.md#决策记录)
