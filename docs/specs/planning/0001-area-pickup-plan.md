# 0001 按片区生成和调整领件草案

Status: ready-for-agent

## 问题陈述

同一网点把已入站包裹按配送片区分堆。网点调度需要快速看清日常谁负责哪堆件，并在请假、人员变化、片区责任调整或现场有积压时，明确改变这批件的领件安排。当天每趟实际带走的件数由配送员扫码领件得出。

## 解决方案

网点调度选择本网点一个班次及要处理的入站批次，系统按配送片区聚合仍在网点的直派件，并把常规责任人在岗的片区填入草案。网点调度可以把具体运单移给另一位当班网点配送员，或先留站。草案显示每组片区、拟领件人、候领件数和未安排原因。按实际扫码办理的领件属于履约，草案用于备货和发布前复核。

## 用户故事

1. 作为网点调度，我希望按班次和入站批次生成草案，以便知道当前这一批包裹的拟领件人和去向。
2. 作为网点员工，我希望清单按网点内部片区分组，以便按现场片区分堆核对。
3. 作为网点调度，我希望看见片区待确认和常规责任人缺岗的包裹，以便及时处理未安排件。
4. 作为网点调度，我希望把一组或指定几票在站件安排给另一位本站当班配送员，以便明确临时支援范围。
5. 作为网点调度，我希望把选中的包裹留站，以便结合现场情况再安排下一趟。
6. 作为网点调度，我希望人员请假、新人到岗或常规片区责任变化后可以重新核对草案，以便用当前人员安排备货。
7. 作为网点调度，我希望查看人工调整的操作者、时间、原因以及原领件人和新领件人，以便之后核对变化。
8. 作为履约的调用方，我希望区分拟领件人和实际领件人，以便按实际扫码统计每趟实领件数。

## 实现决定

- 计划读取履约已确认入站且仍待安排的包裹、网点的配送片区及指定班次的在岗人员。草案的默认建议只用目的地片区常规责任和当班情况。片区待确认、无当班责任人或网点调度明确留站时，逐件显示相应原因。
- 可安排状态由履约提供。已确认上门、投快递柜或交商铺且仍由网点保管的件，进入网点配送员草案。下属驿站件使用分拨清单，驿站改上门走本站任务。异常暂存件在确认可再次配送后才可预排。首版用合成样例提供已确认目的地。
- 一份草案中的同一件只有一个去向。上门按收件地址片区分组，投柜和商铺代收按约定点位片区分组。人工改领件人时保留履约约定和收件地址原片区。
- 临时换人由本站网点调度显式提交，目标是本站当班的配送员。记录调整原因、操作者、时间和受影响件。片区常规责任查询由网点与运力提供，临时决定写入本份草案。
- 每份草案保存版本。再次打开或核对时报告变化的人员、片区及包裹，网点调度重新确认受影响的安排。同一份草案的并发编辑按版本检测冲突。
- 草案使用当前包裹版本，保存草案不改变现行领件授权或实物保管。已更正片区或已作废在站记录的件，在核对草案时标出变化。
- 候领件数从草案条目计数。单趟实领件数由履约按趟次查询，扣除装车回库的件。配送员可以按本次实际带走的件逐件扫。装车回库的件恢复未出库，可供后续趟次按有效授权正常领取。
- 计划使用 Spring Boot、JDBC 和 MySQL。草案保存和调整流水一起提交。在岗人员和常规片区责任由网点与运力接口给出，当前包裹状态由履约接口给出。

## 测试决定

用固定的片区、班次和包裹输入，从 `planning` 应用服务验收草案和招致冲突的动作。核对返回结果和重新加载的草案，版本冲突和调整流水持久化使用真实 MySQL。

| 场景 | 可验收结果 |
| --- | --- |
| 60 件已入站且需送至东区，小陈正常在岗 | 东区组显示 60 件供核对，拟领件人为小陈，所有包裹保持在站。 |
| 同批入站的两票分别约定网点上门和下属驿站自取 | 只有上门件进入网点配送员草案，驿站件可进入目标驿站的分拨单。 |
| 两票分别约定投指定柜子和交指定商铺 | 两票均进入网点直派草案，按各自确认点位的片区归组。 |
| 小陈请假，东区仍有到站件 | 东区显示责任人缺岗和待安排运单。小李只有在网点调度明确选择这些件并提交后才出现在对应行。 |
| 网点调度将东区 12 件调整给当班的小李 | 草案显示对应 12 件的拟领件人更新，仍归东区。可查此次调整的操作者、理由和前后人员。 |
| 网点调度选择未上班或外网点人员 | 调整被拒绝，重新打开后草案内容和调整记录保持原样。 |
| 同一网点调度在两个页面打开同一版本，再分别提交修改 | 前一笔有效修改可查，后一笔得到版本冲突，重新核对后才能提交。 |
| 草案引用的在站件已被其他生效计划领走 | 核对时标出该件不可安排。原有的实物交接仍可查。 |
| 草案保存后，网点调度更正其中一件的片区或作废其入站 | 核对时标出版本变化，原草案可查，现行授权与实物保管没有被草案写入改变。 |
| 固定样例中一件已返站且仍待联系，随后网点确认可以再投 | 待联系时显示未安排原因；确认可再投后，才进入新的候领草案。 |

## 范围之外

- 驿站分拨与接收按[驿站交接 Spec](../pickup-station/0001-transfer-and-receiving.md)验收。草案的发布、未领件改派及已领件转交按[领件清单版本规则](../../MODULES.md#领件清单的版本)另行验收。
- 跨网点分拨、装载估算、路线优化与派费结算。

## 补充说明

端到端的交接用例是候领 60 件，配送员本趟成功扫码 48 件，页面显示实领 48 件、仍在站 12 件。重复扫描其中一件时实领数仍为 48。发现 1 件装不下，配送员放回交接区并切换回库模式复扫后，实领为 47 件、仍在站 13 件。该件显示未出库，下趟可按有效授权领走，领件及回库记录都可查。这个用例归扫码交接验收。
