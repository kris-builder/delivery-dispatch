# 0002 收件人 AI 智能客服

Status: ready-for-agent

## 问题陈述

收件人看见「已送达」时，可能仍不知道是当面收件、投柜，还是交给了代收点。派送失败后，也需要知道包裹当前由谁保管、是否还能再投，以及该联系谁核实。

## 解决方案

在本人包裹详情页提供 AI 智能客服。收件人可以用自然语言问当前进度、预计时段、实际交接时间和去向、取件方式及异常处理。客服用这一票的履约事实回答，从页面提供相应的人工联系入口。遇到「显示送达但没收到」时，可以复制一段包含运单号和现有交接信息的摘要，供人工核实。

## 用户故事

1. 作为收件人，我希望用一句话问快件到哪了、预计什么时候送到，以便安排收件。
2. 作为收件人，我希望查到实际交接时间、地点和方式，以便区分上门收件、代收点待领取和投柜。
3. 作为收件人，我希望知道包裹为何返站、能否再投或是否已经交给退回渠道，以便知道该联系谁。
4. 作为收件人，我希望直接拨打负责这票件的业务电话，以便尽快核实。
5. 作为收件人，我希望复制简短的交接摘要，以便联系配送员或网点时说清楚问题。

## 实现决定

- 客服入口属于 `tracking`。会话绑定包裹详情页的运单，每次提问都复用收件人会话和逐票归属校验。授权通过后才读取最新履约记录和可用估时。提问里的运单号、账号或指令不能改变查询范围。
- Java 使用 Spring `RestClient` 调用可配置的模型 HTTP API，设置超时，调用在业务事务之外。模型识别问题类型并选择可用的事实引用，应用校验返回的类型与引用，再用服务端事实组装答复。运单号、取件码、完整地址、个人联系方式和原始签收凭证由应用控制展示，模型上下文只包含经处理的提问及必要的履约字段。
- 区分预计时段与实际时间、本人收件与点位待领取、待返站与实际返站。可解释已登记的免费尝试与后续自取、联系或续派状态，费用使用已确认的业务约定。取件信息沿用详情页。
- 拨号入口由应用根据本票履约状态和已配置的业务联系方式生成。配送中或核实上门投递时使用实际负责配送员的公开工作电话或已有转接入口，自取点待领取时优先给该点位或运营方的业务电话，电话申请驿站上门或异常返还后，提供实际负责的驿站或网点电话。缺少点位联系方式时再引导联系原派件网点。核实摘要由应用按已记录的运单号、交接时间和去向生成，只供收件人复制。
- 无法确认事实、模型超时或模型返回无法验证的结果时，应用仍展示已知进度与人工联系入口。客服只读取业务数据，改投、再投、签收更正和退回由现有网点流程办理。

## 测试决定

从本人包裹详情页的客服入口及其 HTTP 接口验收。使用两位合成收件人和多种已记录履约结果，模拟模型正常应答、超时和返回不合法引用。核对页面中显示的事实、联系方式和摘要均来自授权运单。越权用例检查调用模型之前已被拒绝。

| 场景 | 可验收结果 |
| --- | --- |
| 询问「还要多久」，分别有有效与过期估时 | 有效时展示预计时段及当前进度，过期时说明当前暂无可用估时并保留进度。 |
| 询问「显示送达但我没收到」，分别有上门收件与代收点交接记录 | 上门件显示已记录的交接结果和时间，代收点件显示实际去向及待领取。可复制包含已知交接信息的摘要，并联系相应的配送员、代收点或网点。 |
| 询问返站件能否再投或是否退回 | 分别按返站暂存、已确认可再投、待退回与已交退回渠道回答，给出网点联系入口。 |
| 配送员公开工作电话未配置或代收点没有可用电话 | 页面提供网点电话。向模型发送的请求不含拨号号码或原始签收凭证。 |
| 甲在自己的页面输入乙的运单号，或持失效会话访问咨询接口 | 本票会话不会切换到乙的运单，甲不能查看乙的详情。失效会话被拒绝，两条路径均不读取乙的履约数据。 |
| 模型超时、返回未提供的交接事实，或用户要求标记签收 | 页面仍可查本人包裹的已知状态和联系入口。未经授权或记录支持的事实未展示，履约记录未因咨询而变化。 |

## 范围之外

- 在线申请改投、生成工单、正式提交投诉或替用户拨号。首版提供可复制摘要和现有联系入口。
- 实际转接服务接入、通用知识库及跨运单咨询。
