# 0001 收件人查件与通知演示

Status: ready-for-agent

## 问题陈述

收件人需要知道自己的快件目前在哪、预计什么时候送到，以及最后是送上门还是到指定点位自取。选择自取时，还需要知道实际点位和取件方式。网点需要让这些信息与实际交接记录一致。

## 解决方案

收件人用手机号验证登录后，在「我的包裹」中自动看到本人运单，也可以输入运单号添加关注。详情展示当前进度、约定投递方式、可用预计时段和实际去向。用站内消息和模拟短信发送记录演示预计到达与代收点到件两类提醒。

## 用户故事

1. 作为收件人，我希望登录后看到本人包裹，以便一次查到多票件。
2. 作为收件人，我希望输入运单号添加关注，以便快速找到我要查的包裹。
3. 作为收件人，我希望看见实际进度、约定方式和预计时段，以便安排在家收件或出门取件。
4. 作为收件人，我希望包裹交给代收点后看到具体地点、地址和取件信息，以便找到这票件。
5. 作为收件人，我希望得到预计到达和已到代收点的提醒，以便提前安排收件和及时取件。

## 实现决定

- `tracking` 提供「我的包裹」、包裹详情和关注记录。`identity` 提供服务端已验证的收件人标识及登录手机号。`fulfillment` 提供可信运单资料与已提交履约记录，`eta` 提供可选的预计时段。
- 从 MySQL 按已验证的手机号查运单登记的收件手机号，列表限于本站已有履约记录。添加关注时同时核对运单号和收件手机号，已关注的同一票重复添加时返回当前结果。未找到、归属不符或无法确定唯一匹配时统一提示无法添加。
- 列表、详情、添加关注和消息查询都以当前有效的收件人会话校验访问权限。详情展示可对收件人公开的履约时间线。已有运单详情链接与关注记录的访问仍按当前归属检查。
- 页面沿用同一票运单展示网点入库、分拨、驿站实收、自取和上门的实际阶段。入站或转运异常未解决时展示异常待核及网点联系入口。上门未妥投展示已发生的尝试，协商续派时按已确认约定展示费用和时间。页面分别展示约定投递方式和实际去向。预计时段仅在估时有效时展示。
- 实际上门交给收件人时展示收件结果和时间。本站确认可领取或外部点位实际接收后，展示「待领取」，以及实际点位类型、名称、地址、交接或可取时间和已有取件信息。点位提供的取件码按可信记录展示。异常件继续配送时展示「待当面验收」。收到可信领取确认后显示「已领取」和实际时间。
- 提前提醒使用一次可用的固定估时样例，可在收件人打开查件页前生成。到件提醒由已提交的待领取履约事件触发，例如「已到东门驿站，可领取」。同一事件对同一收件人生成一条站内提醒和对应的模拟短信发送记录，两处可核对同一票件及消息结果。

## 测试决定

从收件人登录后的正常页面及 HTTP 入口验收。使用两个合成手机号、各自的运单、合成代收点和固定估时样例。页面与消息可先用固定数据验收，联调时用收件人会话及已提交履约数据复演。归属查询、关注去重和到件提醒的持久化验收使用真实 MySQL。

| 场景 | 可验收结果 |
| --- | --- |
| 收件人甲登录，数据库中同时有甲、乙两人的运单 | 自动列出甲的运单。用甲的会话访问乙的详情或按号添加时，无法看到乙的运单信息。 |
| 甲两次输入同一票本人运单号，并在退出后重访旧链接 | 两次添加后只有一条关注记录。退出后旧链接要求重新登录。 |
| 甲有约定上门件和约定交代收点件 | 有有效估时时，分别显示预计上门与预计到代收点。估时不可用时，两票都保留当前进度。 |
| 分别有上门收件、本站可自取、驿站接收、成功入柜和商铺接收的履约记录 | 上门件显示实际收件时间。其余显示各自实际地点和待领取。注入可信领取确认后，该件显示实际领取时间。 |
| 先注入有效的估时样例，再提交外部点位接收并重复处理同一事件 | 收件人能查到预计到达及可领取两条站内消息、两条对应的模拟短信记录。接收未提交时没有可领取提醒，重复处理后仍只有一条该提醒。 |

## 范围之外

- AI 智能客服、在线改投、取件回执的上游接入和签收争议处理。
- Redis 在途定位、高德算路、FastAPI 估时，以及真实短信供应商和生产通知投递。
