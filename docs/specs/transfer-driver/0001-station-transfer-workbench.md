# 0001 网点转运司机工作台

Status: ready-for-agent

## 问题陈述

网点调度把一批件分给下属驿站后，转运司机需要查目的地、确认实际装走哪些件，到站和驿站站长核对最后签收多少件。没签收的实物需要带回网点交还，现场缺失的件需要留下核查记录。

## 解决方案

提供司机手机工作台。司机查看本人受指派的分拨批次，和网点操作员核对后确认实际接手。到站后根据同一份实发清单与驿站站长当面核对，查看驿站提交的批签和差异。需要带回的件由网点操作员确认收回后，运送环节才结清。

## 用户故事

1. 作为转运司机，我希望看到本人批次及目标驿站，以便装车时找到应接的货。
2. 作为转运司机，我希望确认实际装走的包裹及当场发现的问题，以便有可核对的网点交接记录。
3. 作为转运司机，我希望和站长看到同一份实发清单及实际签收结果，以便当场分清正常件、拒收件和缺件。
4. 作为转运司机，我希望查到需要带回的件和网点收回确认，以便完成本趟交接。

## 实现决定

- `transfer-driver` 提供司机页面与操作入口。用服务端会话校验司机岗位、所属网点及该批次的有效指派。`pickup-station` 提供批次和驿站对账，`fulfillment` 写实际保管和逐票交接事件。司机工作台读取同一份记录。
- 每个分拨批次有一个目标驿站。司机与网点操作员核对实际装车件并确认接手，记录经手人、时间和已有外观异常。未装车的件保留待发。隔离待核的异常件继续由网点处理。
- 到站后展示实发清单和现场差异。司机确认所见的破损、错件或缺件，驿站站长确认本次接收并批量签收核对正常的件。已批准继续配送的破损件由站长对照既有凭证逐票处理。实际签收结果由驿站提交后展示给司机。
- 现场未签收且有实物的件，按既有保管记录由司机带回，网点操作员扫码确认收回。缺失件保留最后一次交接记录和交接差异，交网点继续核查。工作台显示待交还实物；驿站接收及实物回交完成后可结清司机作业，已移交网点的缺件异常仍可跟进。
- 接手、差异确认和回交沿用原批次及逐票标识。服务端按当前指派、批次版本和保管状态校验，重复提交同一操作返回原结果。

## 测试决定

从司机工作台及关联的网点、驿站 HTTP 入口联调。用合成司机、网点员工、驿站和运单验证权限、实际接手、返回异常实物和重试。持久化结果核对批次清单与逐票交接事件。

| 场景 | 可验收结果 |
| --- | --- |
| 分拨计划 20 件，司机与网点实际交接装车 19 件 | 司机看到实发 19 件，另 1 件仍在网点待发，驿站按 19 件核对。 |
| 实发 20 件，到站查出 18 件正常、1 件破损、1 件缺失 | 驿站站长批量签收 18 件。司机看到待带回的破损件和待网点核查的缺件，两票都未进入驿站正常库存。 |
| 司机带回破损件，网点操作员确认实物收回 | 报表可查回交双方与时间，实物保管转回网点。缺件核查仍可跟进。 |
| 其他司机访问该批次，司机代替驿站签收，或重复确认接手 | 无权限操作被拒绝。重复确认不增加实发件数或交接记录。 |

## 范围之外

- 车队排班、车辆维保、司机位置或路径优化。
- 驿站上门、单票末端派送及理赔结论。
