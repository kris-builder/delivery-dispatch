# 0002 异常包裹跟进、遗失与找回

Status: ready-for-agent

## 问题陈述

上游来件、网点保管、司机转运、驿站保管和配送员投递都可能出现异常。经手人员需要在自己的工作台查到相关件，明确当前谁跟进、什么时候到期。缺失件需要有遗失与赔付的处理入口，找到实物后需要可追溯地恢复库存。

## 解决方案

包裹履约统一登记异常。网点、司机、配送员和驿站按权限查看同一条异常记录。按发生环节和交接证据确定责任范围及处理人。仍下落不明的件到期转为遗失待核，核实后由责任方发起赔付申请。期限内找到时，获授权的接收方扫码恢复在站状态。

## 用户故事

1. 作为网点或驿站工作人员，我希望看到本单位负责及参与交接的异常，以便核对处理记录。
2. 作为司机或配送员，我希望查到本人经手批次或本人配送件中的异常，以便及时上报和处理。
3. 作为异常处理人，我希望看到查找期限、补充证据并在确认遗失后发起赔付申请。
4. 作为找到实物的接收单位，我希望扫码恢复库存，以便继续按有效约定安排这票件。

## 实现决定

- `fulfillment` 管理异常类型、当前状态、发现环节、最后可信交接、实际或最后已知保管方、责任环节、处理方和截止时间。仓内异常归当时保管的网点或驿站，转运和配送异常关联当段司机或配送员及所属单位。按作业证据判断异常发生环节，暂不能判定时保留待核并指定跟进人。调整归属时记录操作者、时间和依据。
- 网点与驿站员工查看本单位负责及本单位实际参与交接的异常。司机只查看本人受指派批次相关的异常，网点配送员与驿站配送员只查看本人经手的件。修改、转派、结案和发起赔付以服务端岗位和本条异常的处理权限为准。网点仍可跟进驿站未签收的件，驿站能看到该次交接的差异。
- 实物去向不明且到了配置的查找期限仍未找回时，后台任务将异常标为「遗失待核」，保留最后已知交接。责任方复核确认后发起赔付申请，保存申请人、依据、时间及业务状态。同一遗失异常只产生一份有效申请。仍有实物的破损、暂存、待退回等异常到期进入对应逾期待办。
- 期限内找到时，由有权限的接收人员扫码确认实物、所在地点和原异常，校验运单与当前库存。用原包裹标识追加找回入库记录，结清本次缺失，保留首次实收、原交接及异常历史。通过当前归属和其他拦截校验后才可重新分拨或派送。
- 超时处理、找回入库与赔付申请都校验同一条异常的当前状态和版本，在 MySQL 事务内提交结果和事件。已进入遗失流程后又找到的件也能登记实物，暂列复核，由责任方核对已有赔付申请再处理。

## 测试决定

从异常清单、扫码找回及赔付申请 HTTP 入口验收，并核对后台超时任务。用合成网点、驿站、司机和两类配送员验证授权。用真实 MySQL 验超时与找回并发、异常事件及赔付申请去重。

| 场景 | 可验收结果 |
| --- | --- |
| 司机送到驿站现场少一件，驿站未签收 | 网点和该司机可查异常，目标驿站可见交接差异。网点承担转运环节的跟进，其他司机或驿站无法操作。 |
| 驿站已入库件盘点缺失，另有一票是驿站配送员已领走后发生异常 | 两票分别归驿站保管和对应配送环节，进入各自待办，最后可信交接可查。 |
| 缺失到期，后台任务重复执行，处理人重复发起赔付 | 只发生一次超时转换，确认后只生成一份有效赔付申请。 |
| 破损件仍在网点，超过处理期限 | 网点能看到对应逾期待办，实际保管与异常类型保持准确。 |
| 期限内找到缺失件，两次重复扫描 | 用同一运单恢复库存并结清缺失，新增一次找回入库记录，实收不重复计数。 |
| 找回入库与超时处理并发，或发起赔付后才找回 | 两种状态转换按提交后事实互斥。已走赔付流程时记录实物发现并转人工复核。 |
