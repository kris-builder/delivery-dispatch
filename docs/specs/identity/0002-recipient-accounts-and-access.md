# 0002 收件人账号与登录

Status: ready-for-agent

## 问题陈述

收件人需要在自己的身份下查件和咨询。系统需要验证谁在使用收件人入口，并为后续的运单归属检查提供稳定的身份标识。

## 解决方案

在账号与身份模块中增加收件人账号。收件人在独立入口用手机号和验证码登录，登录后由服务端会话提供已验证的收件人标识。演示用预置的合成账号和模拟发送。查件与客服根据运单归属判断收件人能访问哪一票。

## 用户故事

1. 作为收件人，我希望用手机号和验证码登录，以便进入收件人服务。
2. 作为收件人，我希望主动退出，以便在共用设备上收回访问。
3. 作为收件人，我希望我的身份只用于收件人入口，以便员工端和收件人端的权限分别校验。

## 实现决定

- `identity` 管理收件人账号、验证码校验与会话。收件人账号有稳定标识和唯一的规范化登录手机号，无员工岗位或网点绑定，员工账号管理入口无权管理它。
- 使用 Spring Security 服务端会话。收件人入口解析收件人类型的会话，员工入口解析员工类型的会话。登录成功后建立收件人会话，退出或超时后要求重新登录。
- 验证码绑定对应账号和登录用途，有有效期、仅能成功使用一次。服务端限制发送频率与验证次数。演示使用模拟发送接口，公开登录接口和应用日志不返回验证码。
- 服务端向收件人服务提供已验证的收件人标识及其登录手机号。查件、添加包裹和客服由 `tracking` 校验目标运单的归属，使用服务端已验证手机号和可信运单资料。客户端提供的身份或手机号字段无授权效力。

## 测试决定

从公开登录入口和受保护的 HTTP 入口验收。使用两位合成收件人、一个合成员工和模拟验证码发送服务。收件人登录与会话测试可独立运行。

| 场景 | 可验收结果 |
| --- | --- |
| 收件人使用本人有效验证码登录 | 服务端建立收件人会话，受保护入口解析到对应的收件人标识。 |
| 验证码错误、到期、已用过、用于另一手机号或请求过于频繁 | 登录或发送请求被拒绝，无有效会话产生。 |
| 收件人退出或会话超时 | 旧会话无法访问受保护入口。 |
| 收件人访问员工入口、员工会话访问收件人入口 | 两个方向均拒绝访问，普通收件人无法获得员工岗位与权限。 |

## 范围之外

- 真实短信供应商、面向公众的注册、换绑手机号和账号找回。
- 运单归属确认、包裹进度展示和 AI 客服验收。对应流程见[收件人服务](../../MODULES.md#收件人服务)。

## 补充说明

联调时给两位合成收件人各准备一票运单，登记各自的合成手机号。让第一位收件人分别查询本人和第二位的运单，验证登录和逐票授权分别起作用。
