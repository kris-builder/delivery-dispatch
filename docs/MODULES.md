## 模块及接口

接口描述调用方需要知道的输入、结果和业务规则。正常操作与自动测试通过同一个模块接口，观察结果与持久化记录。

### 网点与运力 `station`

- 提供本网点的有效片区、常规责任人及指定时点在岗的人员。片区查询供履约校验，在岗人员查询供计划使用。
- 网点调度维护本网点配送员、班次、请假、常规责任及「街道 + 小区 → 片区」规则。驿站站长维护本驿站的配送员与班次。两类档案按所属单位查询。 [station/0001 片区责任与当班人员](specs/station/0001-station-areas-and-capacity.md)
- 提供网点与下属驿站关系及服务点位。网点调度分拨前校验驿站归属。

### 配送计划 `planning`

| 操作 | 接口与可观察结果 |
| --- | --- |
| 生成草案 | 网点调度选择批次和班次，把网点直派件按目的地片区分给在岗的网点配送员，显示候领件和未安排原因。 |
| 人工调整 | 网点调度选一组或若干待领件，改给本网点当班人员或留站。调整保存操作者、原因和结果。 |
| 发布计划 | 网点调度确认发布直派清单。核对版本、人员范围和实物状态，遇到冲突时返回运单。 |
| 调整留站件 | 按最新可安排的在站件和当班人员拟定调整。异常暂存件须先完成跟进，确认可再次配送后才可选。 |

计划模块拥有草案、候领清单、人工调整和生效版本。发布时与履约模块在同一数据库事务校验并更新出站授权。 [planning/0001 按片区生成和调整领件草案](specs/planning/0001-area-pickup-plan.md)

### 包裹履约 `fulfillment`

| 操作 | 接口与可观察结果 |
| --- | --- |
| 扫码入站 | 按可信上游批次核对实收。正常件匹配片区；入站破损和无法识别的实物登记异常并隔离，无单号用临时异常编号。 |
| 人工补分 | 地址缺失或匹配失败时，员工在待分配列表为在站件选择本站有效片区，记录操作人和时间。 |
| 更正入站记录 | 网点调度更正网点分区或作废错录。追加更正事件，已交接或仍有现行领件、分拨授权的件提示冲突。 |
| 查件与库存台账 | 按批次区分应到、实收、异常暂存和核对后的应到未收，按运单或临时异常编号查交接记录。 |
| 接收计划的出站授权 | 核对包裹的版本和实物状态后更新获准领件人与计划版本。每件包裹最多一份现行出站授权。交接记录作为实物归属的依据。 |
| 按趟连续扫码领件与装车回库 | 配送员在领件模式逐件扫描，第一笔成功领件建立本趟。装不下的件放回交接区，在回库模式复扫。两种操作逐票返回结果，工作台显示扣除装车回库后的实领件数。实物差异由网点复核。 |
| 确认投递约定 | 记录每票件约定的上门或到点自取、目的地和确认依据。在已确认的范围内办理改投，实际交接后另记实际方式和去向。 |
| 登记投递、收件确认与返站 | 核对实际持有人和允许的业务状态。记录投递去向、凭证或失败原因。返站件由实际收回的网点或驿站跟进，按上门次数与已确认约定判断是否可再投。 |
| 跟进异常与办理退回 | 网点、驿站、司机和配送员按职责查相关异常。按实物状况和处理期限办理找回、退回或遗失核查。 |
| 查签收争议 | 网点按运单查看交接、破损照片和实际去向，记录争议核实结果。自助申诉和外部代收点回执接入各自评估。 |

扫码和配送结果都走履约模块的状态写入接口。同一业务事务里更新当前状态并追加操作事件，记录运单、动作、操作账号和服务端时间。交接事件另记责任转移双方，可获取可信设备标识时随事件保存。状态规则拒绝未入站先领件、已完成再领件等非法操作，并对重复提交给出原结果。状态与事件的一致性用真实 MySQL 验证。 [fulfillment/0001 扫码入站、自动分区与查件](specs/fulfillment/0001-inbound-scan-and-area-matching.md)

弱网时首版明确显示提交结果，支持断网恢复后重试。若现场确有持续离线录入需求，再为配送端增加本地待同步队列。补传时按当前状态和授权重新校验，冲突反馈给操作者，出站仍以服务端确认作为交接记录。凭证与人员授权是查证依据，出站到送达的用时可供异常排查。

运营日报可从实收入站、实际交接和配送结果汇总。先明确统计时段及签收率分母，再独立立规格。

### 下属驿站

`pickup-station` 管理驿站应收清单、现场签收差异、上门任务与计件。网点调度指派司机，网点操作员和司机核对实发。司机到站后和驿站站长共同验货，正常件一次批量签收。破损、缺件、错件逐票记为驿站未签收，由网点跟进。 [驿站分拨交接 Spec](specs/pickup-station/0001-transfer-and-receiving.md)

驿站站长接客户电话后确认本驿站保管的包裹改上门，指派本驿站配送员并保留变更历史。前两次免费，之后的收费续派须协商确认。成功上门后为实际完成者记一次计件。 [驿站上门与计件 Spec](specs/pickup-station/0002-home-delivery-service.md)

### 账号与身份 `identity`

服务端会话按岗位和所属单位授权。网点调度发布清单，转运司机操作本人分拨批次，驿站站长办理本站签收和上门派工，驿站分拣员处理本站已签收件的上架，两类配送员操作各自获准的配送件。 [工程规范](ENGINEERING.md#用户认证和权限设计) · [identity/0001 网点与驿站员工权限](specs/identity/0001-station-accounts-and-access.md)

收件人用手机号验证码登录，`identity` 管理收件人账号和会话，为服务端提供已验证的收件人标识。收件人身份没有员工岗位或网点权限，查件与咨询前由收件人服务校验目标运单的归属。演示使用预置的合成账号和模拟验证码发送。 [identity/0002 收件人账号与登录](specs/identity/0002-recipient-accounts-and-access.md)

## 模块依赖

| 调用模块 | 依赖模块 | 用途 |
| --- | --- | --- |
| 账号与身份 | 网点与运力 | 核对账号绑定的网点和配送员。 |
| 包裹履约 | 网点与运力 | 匹配入站地址，校验人工补分时选择的片区和投递约定引用的自取点。 |
| 配送计划 | 网点与运力、包裹履约 | 读取片区责任、当班人员和在站包裹。发布时调用履约接口更新出站授权。 |
| 下属驿站 | 网点与运力、账号与身份、包裹履约 | 校验下属关系与驿站权限，读取实际发出和接收，办理分拨、收货对账及本站上门服务。 |
| 转运司机工作台 | 账号与身份、下属驿站、包裹履约 | 校验司机指派，查本人批次，办理装车接手、现场差异确认及实物回交。 |
| 在途查件 | 账号与身份、包裹履约 | 校验位置上报和网点查询权限，读取实际趟次、已确认的停靠顺序和当前配送进度。 |
| 预计送达 | 在途查件 | 接收路段耗时和目标站前的未完成停靠点，返回估算结果。 |
| 收件人服务 | 账号与身份、包裹履约、预计送达（可选输入） | 取得登录收件人身份，校验运单归属后读取可见履约进度。有可用的预计时段时补充显示。 |

员工和收件人入口分别读取对应类型的服务端身份。业务模块按资源归属检查权限，并写入各自负责的数据。接口样例可供调用方先做模块内验收，再接实际的数据提供方。

## 履约状态与计划发布

接下来按下表讨论发布、领件和返站。表内命令是下一批规格的讨论稿，先验一票件的实物和责任从哪里转到哪里。

实物保管、配送尝试、领件授权和异常待办分别记录。保管方可能是网点、转运司机、配送员、驿站、自取点或收件人。异常待办记录发现环节、谁跟进与结案结果。

### 入站及转运验收异常

网点首次验货发现破损或缺单号，登记上游交接待核。网点记录完好出库、驿站现场发现破损或缺失时，登记转运交接差异，由网点追查对应批次和司机交接。异常保存发现环节、当前实物保管、跟进方、运单或临时编号，以及现场说明和凭证。驿站只有签收的正常件进入正常库存。

| 异常处置 | 操作与结果 |
| --- | --- |
| 缺单号 | 网点调度与上游核对后补齐真实运单号，保留临时编号、确认依据和操作记录。核对相符且其他放行条件满足后才放行。 |
| 外包装破损 | 发现单位拍照登记并联系收件人。内件未经检查时记录为未核验。收件人可选择退回并转理赔处理，也可同意继续送。继续送时保留「异常件，待当面验收」标记，检查无问题后记录签收，发现内损或拒收则记录后交回。 |
| 已确认内件破损 | 告知收件人破损情况，登记拒收或待退回，实际交出后跟踪退回与理赔。 |

责任核查按交接时记录的状况和当时保管方追溯。驿站签收后、配送员领件前新增破损由驿站跟进。配送员确认接手后新发生的破损归该配送环节核查。此前已登记的损伤继续关联原证据，收件人拒收时保留其原因和包裹实际去向。 [《快递暂行条例》第二十六条](https://www.mee.gov.cn/ywgz/fgbz/xzfg/202610/t20261009_1175902.shtml)

### 异常归属、遗失与找回

责任方在各自工作台查看和跟进，参与交接的人员可查看本段差异。仍下落不明的件到期转为遗失待核，经责任方确认后可发起赔付申请。实物仍在的件按原类型进入逾期处理。期限内找到时，由接收单位扫码按原运单恢复库存，保留原异常和交接历史。 [异常跟进与找回 Spec](specs/fulfillment/0002-exception-ownership-and-recovery.md)

### 上门派送与到点自取

每票件记录履约方式、约定目的地、确认来源和实际去向。已确认的上门、快递柜和普通商铺代收走网点直派；已确认的下属驿站自取走分拨。柜满、尺寸不合时，实物仍由持有人保管，按原同意范围或再次确认的结果处理。

| 情形 | 实物怎么走 | 收件人看到什么 |
| --- | --- | --- |
| 网点直派上门 | 网点调度发布直派清单，网点配送员领件送到约定地址。 | 配送进度和实际交接时间。 |
| 下属驿站自取 | 网点转运司机交货，驿站站长现场验收并批量签收正常件，再确认可领取。 | 运往驿站、驿站待领取或实际已领取。异常件留待网点跟进。 |
| 驿站已收，改上门 | 驿站站长确认服务，指派本驿站配送员，后者扫码接手并上门。前两次按免费规则办理。 | 上门安排、配送进度和实际交接时间。 |
| 外部柜或商铺自取 | 网点配送员按直派清单扫码领取，送到已确认的点位并登记实际交接。 | 点位、可领取状态与可用取件信息。 |

自取由实际保管单位或可信回执确认。本站自取沿用可领取与实际领取规则。柜机等外部点位的改投以真实取回交接为准。寄件人预约上门揽收属于独立业务。

柜机或商铺的点位服务费按合作约定结算，对应实际办理交件的网点配送员或其网点账户。直派发布只生成领件授权，点位费用与收件人续派费用、驿站配送员计件分别核对。

### 领件清单的版本

- 发布以本站、班次和本次明确选中的运单为范围。未领且仍在本站的件可以直接改派，替换对应授权。已领取的件按当前状态显示待转交、待返站或已交付，不进入直接改派提交。
- 网点调度或驿站站长在各自单位明确留站或撤销时，同一事务撤销该件未执行的授权。已撤销、已领或已到期的条目退出候领。建议尚未领走的件在本班次内可留给下一趟，跨班次重新确认领件授权。
- 调度可以先确认并发布未领件，再单独处理已领件。一次明确选中的直接改派仍采用原子提交。提交时若有件刚被领走或版本变化，返回冲突运单供调度重新确认。

已领未交付时，由网点调度按实物状态确认转交方案。件仍在交接区的，可由原配送员复扫归还后重新授权。派送途中由原配送员确认交出、接手人扫码确认接收，实物归属在接收后变更。待返站件先办理收回和异常处理，已签收或已交点位的件沿用实际交付记录，后续操作以实际取回为前提。

改派流水记录运单、操作人、原与新配送员、原因、状态、操作时间和确认结果。已领件还要关联实际交出与接收记录。 [计划发布与交接一致性](ARCHITECTURE.md#计划发布与交接一致性)

### 趟次与包裹交接

| 命令和操作者 | 前置事实 | 提交后的事实与事件 |
| --- | --- | --- |
| 配送员按趟扫码领件 | 本人有本站当前班次的有效清单，包裹在站且授权给本人。 | 首笔成功领件建立本趟，逐件扫码记录配送员接手、趟次和已使用的授权。扫完即可装车发走。系统将领件时间记为接手时间。 |
| 配送员装车回库 | 本人持有本趟领到的该件，该件尚无投递结果或待返站异常，实物已放回出发单位交接区。 | 复扫后恢复「未出库」，移出本趟实领，留待该单位后续趟次。 |
| 配送员登记投递失败 | 该件仍由本人持有，已有当前趟次。 | 记录实际尝试及失败原因，按次数和服务来源确定继续免费投递、经同意改投或返站跟进。实物保管在交接后变化。 |
| 配送员登记投递 | 本人实际持有且当前尝试允许投递，实际去向符合已确认的投递约定。 | 上门收件和自取点接收分别记录实际去向、时间及所需凭证。外部自取点接收后等待收件人领取。 |
| 出发单位扫码收回异常件 | 配送员带回实物，网点操作员或驿站站长核对收到。 | 记录返站交接，实际保管转回该单位，异常件进入暂存与待联系。 |
| 出发单位联系收件人并跟进 | 异常件已确认返站，仍由该单位保管。 | 记录联系时间和结果，确认可再投后重新安排。 |
| 办理退回件实物交接 | 处理期限已到且仍未解决，当前保管单位核对退回要求并实际交件。 | 记录退回交接和时间，需先退回上级网点时保留该段交接记录。 |
| 配送员 A 确认交件，配送员 B 扫码接手 | A 实际持有且该件可转交，所属单位负责人确认接收人 B。 | B 接收后转移实际保管和待送任务，逐步记录改派与交接。 |
| 关趟或处理异常趟次 | 本趟实领件均有实际投递、转交或返站结果。 | 实物去向未确认时，显示待核及责任人；结清后关趟。 |
| 所属单位的授权人员更正错误投递结果 | 已核对原结果和更正依据。 | 追加更正事件及原因，保留原结果及实物待核记录。 |

装车回库按该件的实际操作处理。联系不上时依据已发生的尝试和当前约定处理。需要返站时登记真实交接。扫完即可发车，收件人可见的「配送员已领件」以实际交接为准，扫码时间表示接手时间。

重复领件、装车回库、送达、返站和转交确认按操作标识返回原结果。对已改变实物状态的件发起不同操作时重新校验。记录事件、实物保管和需要的待办在短事务中提交。

### 联系不上收件人的异常件

按已确认的上门服务累计符合条件的实际投递尝试。同一次失败重报、电话拨打次数、装车回库或配送方原因未实际投递均不计入免费次数。首版配置前两次免费，换人、换趟或返站重排沿用同一服务的计数。首次未妥投后可按约继续免费投递。

| 两次未妥投后的分支 | 处理 |
| --- | --- |
| 网点直派 | 有适用本票的驿站或快递柜投递同意时，可按确认的点位实际交接。需要新同意且联系不上时返网点暂存。收件人仍要求上门时，可先告知费用并商定续派。 |
| 驿站上门 | 扫码交回本驿站并暂存，联系上后确认恢复自取，或告知收费标准并取得同意后再次安排上门。 |

返站、交给已获同意的点位和交退回渠道都按实际交接确认。仍联系不上时进入待联系，达到处理期限后按退回规则跟进。 [《快递服务 第3部分：服务环节》GB/T 27917.3-2023](https://openstd.samr.gov.cn/bzgk/std/newGbInfo?hcno=A47355CEF08AFBF7CBDB2E5C8C590532&refer=outter) · [《快递市场管理办法》](https://xxgk.mot.gov.cn/2020/jigou/fgs/202401/t20240104_3980683.html)

## 转运司机工作台

`transfer-driver` 供本网点司机查看获派批次、确认实际装车、与驿站当场核对和查看异常件回交。驿站站长提交批量签收，网点操作员确认带回的异常实物，司机从同一批次跟踪两方结果。 [transfer-driver/0001 网点转运司机工作台](specs/transfer-driver/0001-station-transfer-workbench.md)

## 配送员工作台

配送员工作台 `courier` 共用按趟领件、装车回库和投递入口。网点配送员读网点直派清单，驿站配送员读本驿站已分配的上门任务，回库和返站回到各自出发单位。身份、所属单位、包裹现行授权和保管事实共同决定能操作的件。 [courier/0001 按趟领件与配送工作台](specs/courier/0001-trip-delivery-workbench.md)

## 收件人服务

收件人服务 `tracking` 从服务端会话取得收件人标识和已验证的手机号。按运单登记的手机号查本人包裹。手动按运单号添加时同样核验归属，适用于快速定位并关注某票件。手机号不匹配或无法确认运单时，提示无法添加，运单详情保持受限。客服会话对应一票已授权的运单。 [tracking/0001 收件人查件与通知演示](specs/tracking/0001-recipient-parcel-tracking.md)

| 功能 | 业务结果 |
| --- | --- |
| 我的包裹 | 自动列出本站有记录的本人运单，也可用运单号查找并添加关注。 |
| 包裹详情 | 展示入站、派送、约定方式和实际去向。有效估时时按约定区分「预计上门」和「预计到指定取件点」，并显示更新时间。确认可自取后展示「待领取」、实际点位类型、名称、地址和可用取件信息。 |
| AI 智能客服 | 用本票履约记录回答当前进度、预计时段、实际交接时间和去向、取件方式及异常处理。按包裹当前情况提供配送员、代收点或网点的联系入口。 [tracking/0002 收件人 AI 智能客服](specs/tracking/0002-recipient-ai-support.md) |

客服第一版只读。「显示送达但没收到」时，可复制运单号、交接时间和已记录去向，联系对应的工作人员核实。拨号入口由应用提供，配送员使用可公开的工作电话或已配置的转接入口，业务联系信息缺失时提供网点电话。改投、签收更正、再投和退回按网点操作流程办理。信息不足或模型不可用时，页面保留已知进度和联系入口。

收件人通知首版做演示。用站内消息和模拟短信发送记录展示「预计下午到达」与「已到某自取点，可领取」。提前提醒用固定估时样例验收，正式输入接已确认的停靠顺序和有效定位。可领取提醒由已提交的待领取履约事件触发，同一事件只产生一条提醒。

## 在途查件与预计送达

客户催件时，网点需要查配送员最近在哪、这票件前面还有几站。收件人查件页需要能区分预计送达时段和实际投递时间。两项交付共用有效趟次及履约进度，各自验收。

| 模块 | 业务场景 | 选定实现和验收 |
| --- | --- | --- |
| 在途查件 `presence` | 网点按运单查看实际配送员最近上报的位置和时间。有已确认的停靠顺序时，查目标件之前还有几站、沿途还有多远。 | Redis 按趟次保存最近有效点位，按已确认的剩余停靠顺序调用高德算路。位置不可用时仍可按已知顺序查看剩余站点。 [presence/0001 在途位置与剩余路程](specs/presence/0001-trip-location-and-remaining-route.md) |
| 预计送达 `eta` | 收件人看预计时段，网点能查估计耗时及其依据。 | Java 将有效路线的道路耗时和前序未完成停靠点交给 FastAPI。Python 把道路耗时与途中停靠耗时合并。输入不足时展示已有履约进度。 [eta/0001 在途预计送达时段](specs/eta/0001-in-transit-delivery-estimate.md) |

配送员工作台确认停靠点和顺序。一次停靠可处理多票件，剩余站数按站点计。演示用合成停靠点坐标与参考停靠耗时。顺序修改、已完成、跳过和返站按当前趟次版本重新核对，估时只使用计算当时已取得的输入。地址不详等需网点接手的异常由包裹履约直接写入 MySQL 待办。运营统计使用已有业务记录汇总。
